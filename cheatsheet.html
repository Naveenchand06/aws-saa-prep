SAA-C03 One-Stop Cheatsheet

For people who already run things on AWS (EC2, ECS/EKS, RDS/Aurora, VPC, subnets, security groups, NACLs, NAT). It skips what you already know and covers what the exam actually tests: the deciding details, limits, traps and scenario patterns. Read it, take a few practice exams, then book the real one.

Checked against the official SAA-C03 exam guide v1.1 (published 29 Oct 2026).

Cheapest Middle Priciest Trap

How to use this page: (1) Read sections 0–3 closely: they decide most questions. (2) Skim the service sections and mark anything that surprises you. (3) Do 3–4 full practice runs in the practice exam and look up every miss here with the search box. (4) Once you score 80%+ twice in a row, read sections 0, 1, 2 and 17 again and book the exam.

Find the adjective first (cheapest, least overhead, lowest latency, survives a Region failure), then pick the service built for it. Usually two options would both work. The right one matches the adjective.

What the questions look like: a 3–6 sentence scenario (company, current setup, problem) and then one constraint in capitals: MOST cost-effective, LEAST operational overhead, MOST secure, highest availability, minimal application changes, lowest latency. All four options are usually real architectures. Three of them break the constraint.

Common themes in recent exams: serverless and event-driven pipelines (S3 → EventBridge/SQS → Lambda → DynamoDB), multi-account governance (Organizations, SCPs, Control Tower, IAM Identity Center, RAM), hybrid connectivity (Direct Connect + VPN, Transit Gateway, Route 53 Resolver), data lakes (S3 + Glue + Athena + Lake Formation), containers (ECS/EKS on Fargate), and "fix this bill" cost scenarios.

1. Constraint words → how to choose

The capitalised phrase in the question is the real question.

Question saysPick the option that…Usually eliminates
LEAST operational overheadIs managed or serverless, with fewest moving partsAnything on EC2, cron on an instance, custom scripts, self-run Kafka/Redis/DB.
MOST cost-effectivePays only for use, picks the cheapest tier that still meets the requirementProvisioned-for-peak, Multi-site DR, io2 where gp3 fits, NAT where an endpoint fits.
MOST secureUses least privilege, private paths, temporary credentials, encryption with your own KMS keyAccess keys on instances, public buckets, 0.0.0.0/0, sharing credentials.
Highly availableSpans multiple AZs with automatic failoverSingle instance, single AZ, single NAT, one EBS volume.
Survive Region failure / DRReplicates across Regions, with Route 53 failoverMulti-AZ alone, which never crosses Regions.
Minimal code changesIs a drop-in: RDS Proxy, DAX, ElastiCache, ALB, a bigger instanceRewrites to Lambda/DynamoDB, even when they'd be "better".
Scalable / unpredictable trafficAuto Scaling, on-demand modes, serverlessFixed fleets, provisioned capacity sized for today.
Decouple / absorb spikesPuts SQS between the tiersSynchronous calls, bigger instances.
Near real-time vs real-timeNear = Firehose (buffered) · Real = Kinesis Data StreamsBatch ETL like Glue jobs or EMR.

Trap "Choose TWO/THREE": each correct option has to stand on its own. Don't pick two options that do the same job. The correct pair usually covers two different parts of the problem (e.g. "enable versioning" + "enable MFA Delete").

12. Resilience, DR, migration & transfer

DR strategies (cheapest → fastest)

StrategyRPO / RTOWhat runs in DR Region
1 Backup & restorehours / hoursNothing but backups (AWS Backup cross-Region copies, snapshots, S3 CRR). Rebuild with IaC.
2 Pilot lightminutes / 10s of minData live-replicated (DB replica); app servers off/not created until failover.
3 Warm standbyseconds / minutesFull stack running at small scale; scale up and flip DNS.
4 Multi-site active/active~0 / ~0Full capacity in both Regions taking traffic (DynamoDB global tables, Aurora Global, Route 53 latency/weighted).

RPO = how much data you can lose (time since last good copy). RTO = how long you can be down. Pick the cheapest strategy that meets both numbers. Elastic Disaster Recovery (DRS) = continuous block replication for servers, giving pilot-light cost with RPO in seconds. Route 53 Application Recovery Controller = readiness checks + routing controls for failover.

19. Exam-day playbook

StepDo this
1. Read the last sentence firstFind the constraint (cost / overhead / HA / security / latency) and how many answers to pick.
2. Underline the hard requirements"Within 15 minutes", "no data loss", "existing AD", "minimal code change", "on-premises must keep access".
3. Rule out obvious losersSelf-managed on EC2, long-term access keys, public resources, single AZ, services that don't do the job.
4. Compare the last twoThey usually differ by one property: managed vs self-run, sync vs async, Regional vs global, gateway vs interface endpoint.
5. Don't overthink itThe simplest AWS-native answer that meets every requirement wins. Don't invent requirements the question didn't state.
6. Time-boxSpending > 3 min on one? Pick your best guess, flag it, move on. Answer every question.
7. Review passOnly change an answer if you find a specific word you misread. First instinct is usually right.
