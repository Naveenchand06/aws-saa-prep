SAA-C03 Decision Cheatsheet

Built for someone who already runs this stuff daily. No tutorials — just the discriminators the exam actually tests: which service, which tier, and what it costs relative to the alternatives. EC2 internals and VPC/networking deep-dives are deliberately excluded per your call; those services still appear as one-liners in the glossary so nothing is a blind spot.

Cheapest Middle Priciest Classic trap

Read the question backwards. Find the constraint adjective first — cheapest / least operational overhead / lowest latency / no code change / must survive a Region failure — then pick the service that owns that adjective. Two options are usually both technically correct; only one matches the adjective.

On prices below: approximate us-east-1, on-demand, per GB-month. The exam never asks for a number — it asks for the ordering. Learn the ladder, not the digits.

2. Cost ladders — cheapest to priciest

This is the "what's cheapest, what's most expensive, when do I pick what" view you asked for. Memorise the order and the one-line reason you'd ever climb the ladder.

3 S3 Glacier Instant Retrieval$0.004Archive priced data but you need it back in milliseconds. Quarterly-access data.

8 EBS st1 (Throughput HDD)$0.045Big sequential throughput — logs, data warehouse scans. Not for boot volumes.
9 EBS snapshots$0.05Incremental. Archive tier drops to ~$0.0125 for long-term snapshot retention.

11 EBS gp2$0.10Legacy. Costs more than gp3 and ties IOPS to volume size (3 IOPS/GB). gp3 is nearly always the better answer.
12 EBS io2 / io2 Block Express$0.125 + IOPSOnly when they state a big IOPS number (>16,000) or need 99.999% volume durability.
13 FSx for Windows / Lustre~$0.13–0.14You need SMB+AD, or HPC-grade parallel throughput. Never the "cheap" answer.

Shortcut: object storage < block storage < file storage, at every tier. If a question offers S3 and EFS for the same data and mentions cost, S3 wins unless it explicitly needs a POSIX mount.

3. S3 storage classes in detail

The single most-tested table on the exam. The minimum-duration column is what turns a "cheaper" class into a more expensive one.

Class$/GB-moMin daysAZsRetrieval & when to choose
Standard$0.023—≥3Instant, no retrieval fee. Active data, default landing zone.
Intelligent-Tiering$0.023 → $0.0036—≥3Instant. Auto-moves between tiers, small monitoring fee per object, no retrieval fees. The answer for "unknown or changing access patterns". Monitoring fee makes it a poor fit for millions of tiny objects.
Standard-IA$0.012530≥3Instant, but pay per GB retrieved. Known-infrequent, must-not-lose data.
One Zone-IA$0.010301~20% cheaper than Standard-IA, single AZ. Only for data you can regenerate.
Glacier Instant Retrieval$0.00490≥3Milliseconds, archive pricing. Accessed ~quarterly. Medical images, media archives.
Glacier Flexible Retrieval$0.003690≥3Expedited 1–5 min / Standard 3–5 h / Bulk 5–12 h (bulk free). Backups you rarely restore.
Glacier Deep Archive$0.00099180≥3Standard 12 h / Bulk 48 h. Regulatory retention, 7–10 years. Cheapest possible.

Trap Minimum billable object size is 128 KB for the IA and Glacier classes, and early deletion is charged for the full minimum duration. Lifecycling millions of small log files to Glacier can cost more than leaving them in Standard. Also: all classes share the same 11 nines durability — One Zone-IA differs in availability and AZ blast radius, not durability math.

Typical lifecycle answer: Standard → Standard-IA at 30 days → Glacier Flexible/Deep Archive at 90 days → expire. And Object Lock compliance mode (WORM, not even root can delete) is the answer whenever regulators are mentioned.

4. Databases — which one, and what it costs you

Exam questions are decided by one adjective: relational / key-value / graph / ledger / time-series / warehouse / in-memory. Match the noun, then check the scaling adjective.

ServiceUse whenCost & gotchas
RDS (MySQL, PostgreSQL, MariaDB, Oracle, SQL Server, Db2)Standard relational, lift-and-shift of an existing enginePay per instance-hour + storage. Multi-AZ = failover, not reads. Read replicas = reads, up to 15, manual promotion, cross-Region supported.
Aurora (MySQL/PostgreSQL compatible)You want RDS but faster and more resilient~20% more than RDS but 5×/3× throughput. 6 copies across 3 AZs, storage auto-grows to 128 TiB, up to 15 low-lag replicas, reader endpoint load-balances automatically.
Aurora Serverless v2Spiky or unpredictable load, near-zero at nightBills per ACU-second, scales in seconds. The answer for "don't manage capacity, pay for what you use" on a relational DB.
Aurora Global DatabaseRPO ~1 s, RTO <1 min across RegionsSub-second cross-Region replication, up to 5 secondaries. The only relational answer that meets aggressive cross-Region RPO/RTO.
DynamoDBKey-value, serverless, any scale, flexible schemaOn-demand (spiky, pay per request) vs provisioned + auto scaling (predictable, cheaper). Single-digit ms. Free features worth knowing: TTL (auto-expire rows), Streams (change capture), PITR.
DynamoDB global tablesMulti-Region active-active writesMulti-active. If the question says users write in every Region, this or Aurora Global is the answer.
DAXMicrosecond reads on DynamoDB, minimal code changeAPI-compatible cache. Read-heavy only; doesn't help writes.
ElastiCache — RedisCache + persistence, replication, pub/sub, leaderboards, session storeMulti-AZ with failover. Pick Redis whenever the question needs anything beyond a plain cache.
ElastiCache — MemcachedSimple, multi-threaded, sharded cache, no persistenceNo replication, no failover. If they mention durability or replicas, Memcached is the trap.
MemoryDB for RedisIn-memory speed as the primary durable databaseMulti-AZ transaction log. Rare but appears as the "durable Redis" answer.
RedshiftPetabyte OLAP warehouse, complex joins, BICluster = 24/7 cost; Redshift Serverless for intermittent. Spectrum queries S3 without loading.
DocumentDBMongoDB workloadPure keyword match on "MongoDB-compatible".
NeptuneGraph — social networks, fraud rings, recommendations, "relationships"Keyword: "highly connected data", "traverse relationships".
KeyspacesApache Cassandra workloadServerless Cassandra. Keyword match.
TimestreamTime-series — IoT sensors, metrics over timePurpose-built, auto-tiers recent vs historical data.
QLDBImmutable, cryptographically verifiable ledgerKeyword: "immutable", "verifiable history", "central trusted authority". AWS has wound this service down, but it still appears in the SAA-C03 pool — recognise it, don't plan on it.

Read replica vs Multi-AZ vs global — the most repeated distinction on the whole exam: Multi-AZ = synchronous standby, automatic failover, not readable, survives AZ loss. Read replica = asynchronous, readable, manual promotion, scales reads. Global/cross-Region = survives Region loss.

One of your two focus areas. Every question here reduces to: how much data, how much bandwidth, how much downtime, and does the engine change.

Snow family & the "ship or stream?" arithmetic

Mental formula: days ≈ TB ÷ (10.8 × Gbps), at 100% line rate. Halve the link speed for realism.

So: 100 TB over 1 Gbps ≈ 9–12 days. 80 TB over 100 Mbps ≈ ~2.5 months → obviously Snowball. 500 TB over a 10 Gbps Direct Connect ≈ ~5 days → DataSync wins, no shipping needed.

Rule of thumb the exam wants: if the wire takes more than about a week, ship a device.

DeviceCapacityUse
Snowcone8 TB HDD / 14 TB SSDSmallest, rugged, portable — drones, vehicles, tight spaces. Can ship or use DataSync online.
Snowball Edge Storage Optimized~80 TB usableThe default bulk answer. Petabyte-scale by ordering multiple devices.
Snowball Edge Compute Optimized~42 TB + GPU optionEdge processing before/while shipping — disconnected sites doing ML or preprocessing.
Snowmobileup to 100 PBExabyte-scale, a literal truck. Wound down by AWS, but still appears as a distractor — only correct at extreme PB scale.

10. Traps that catch experienced people

Specifically the ones where real-world instinct points the wrong way on the exam.

You'd instinctively…But the exam wants…
Build it yourself on EC2 because you know howThe managed service, every time "operational overhead" appears. Your competence is not the criterion — the adjective is.
Reach for Multi-AZ to scale readsMulti-AZ is availability only. The standby is invisible. Read replicas scale reads.
Use a NAT gateway for private-subnet AWS API callsVPC endpoints — gateway (free) for S3/DynamoDB, interface for the rest.
Assume Glacier is always cheapestMinimum durations (90/180 days) and 128 KB minimum billable size can make it more expensive for small or short-lived objects.
Pick Standard-IA for "infrequent"If the pattern is unknown or changing, Intelligent-Tiering — it's the one with no retrieval fee.
Use sticky sessions to fix session lossExternalize state to ElastiCache/DynamoDB. Stickiness still loses the session when the instance dies.
Say "SNS" for reliable delivery to one consumerSQS. SNS is push fan-out; pair SNS→SQS when several consumers each need a durable copy.
Treat security groups as having deny rulesSGs are allow-only and stateful. NACLs are stateless and have explicit deny.
Assume one NAT gateway is fineIt's zonal. One per AZ, or an AZ failure takes out egress for everyone.
Reach for Kinesis for any queueIf there's one consumer and no replay requirement, SQS is simpler and cheaper.
Pick Spot for anything to save moneyOnly for interruptible work. A stateful primary database on Spot is always wrong.
Forget the free tiers of data transferInbound is free; S3→CloudFront is free; same-AZ private IP is free. "Reduce transfer cost" usually means routing traffic into one of those.
